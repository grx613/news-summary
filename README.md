# $BOTHUB Аналитика

Сервис: вводите название компании или криптовалюты (по названию либо по тикеру) — получаете AI-саммари свежих публикаций по этому активу.

- Поиск работает по названию и тикеру: `Apple`, `AAPL`, `Bitcoin`, `BTC`, `Газпром`, `GAZP`, `Сбербанк`, `SBER`.
- Поддерживаются три рынка: акции MOEX, акции США, криптовалюты.
- **Кеширование:** первый запрос по тикеру идёт в источники и к модели (10–40 с), повторный — мгновенно из кеша. TTL 26 часов: раз в сутки все тикеры обновляет фоновый крон, так что посетитель почти всегда попадает в кеш.
- **Кнопка «Обновить»** пересобирает саммари мимо кеша, но не чаще раза в 15 минут на тикер — ограничение общее для всех посетителей, кнопка показывает обратный отсчёт.
- Саммари генерирует `claude-haiku-5.5` через OpenAI-совместимый API BotHub.
- По каждому тикеру можно задать вопрос — отвечает ИИ-аналитик. По умолчанию он ищет данные в интернете (`sonar-pro`, Perplexity) и показывает список источников; вопрос с ответом публикуется отдельной страницей.
- **Дивиденды:** на странице каждой бумаги — история выплат, дата закрытия реестра, доходность и суммы по годам; на `/dividends` — календарь ближайших отсечек. Данные бесплатные, модель не вызывается.

## Запуск

```bash
git clone https://github.com/grx613/news-summary.git
cd news-summary
cp .env.example .env    # и вписать BOTHUB_API_KEY
node server.js
# http://localhost:3000
```

Node.js 18+ (нужен встроенный `fetch`). Зависимостей нет — только стандартная библиотека.

`.env` и весь `data/` в репозиторий не попадают: там ключ BotHub, кеш саммари, вопросы и обсуждения. Полный список переменных с умолчаниями — в `.env.example`. Настройки в `.env`:

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `BOTHUB_API_KEY` | — | ключ BotHub (обязателен) |
| `BOTHUB_BASE_URL` | `https://openai.bothub.chat/v1` | OpenAI-совместимый эндпоинт |
| `MODEL` | `claude-haiku-5.5` | модель для саммари |
| `QA_SEARCH_MODEL` | `sonar-pro` | модель с веб-поиском для ответов на вопросы; `off` — отвечать только по кешу новостей |
| `QA_SEARCH_RECENCY` | `month` | фильтр свежести поиска: `day`, `week`, `month`, `year` |
| `QA_FALLBACK_TO_CACHE` | `1` | если поиск недоступен — отвечать по кешу вместо ошибки |
| `PORT` | `3000` | порт |
| `CACHE_TTL_HOURS` | `26` | сколько часов саммари считается свежим |
| `NEWS_WINDOW_HOURS` | `72` | за какой период брать публикации |
| `MAX_NEWS` | `30` | сколько публикаций уходит в модель |
| `MIN_NEWS` | `3` | минимум релевантных публикаций; меньше — 404 без вызова модели |
| `REDDIT_MIN_GAP_MS` | `3000` | пауза между запросами к Reddit (иначе 429) |
| `BASIC_AUTH` | не задано | `user:password` — включить пароль на весь сайт и API |
| `MAX_GENERATIONS_PER_HOUR` | `40` | потолок новых генераций в час по запросам пользователей (крон не считается) |
| `REFRESH_COOLDOWN_MIN` | `15` | минимальный интервал между обновлениями одного тикера кнопкой |
| `CRAWLER_ENABLED` | `1` | включает ежедневный обход всего списка тикеров |
| `CRAWLER_INTERVAL_HOURS` | `24` | как часто крон обновляет каждый тикер |
| `CRAWLER_CONCURRENCY` | `2` | сколько тикеров собирается одновременно |
| `CRAWLER_GAP_MS` | `1500` | пауза между тикерами, чтобы не долбить источники залпом |
| `US_UNIVERSE_LIMIT` | `130` | сколько верхних бумаг США берётся из скринера Nasdaq (после чистки ~115) |
| `CRYPTO_UNIVERSE_LIMIT` | `50` | сколько монет берётся из топа CoinGecko |
| `DIVIDENDS_ENABLED` | `1` | ежедневный сбор дивидендов (`0` — не ходить в dohod и stockanalysis) |
| `DIVIDENDS_INTERVAL_HOURS` | `24` | как часто обновляются дивиденды |
| `INDICES_ENABLED` | `1` | сбор значений индексов (`0` — не ходить на Мосбиржу и в CNBC) |
| `INDICES_QUOTE_MIN` | `5` | как часто обновляются значения индексов, в минутах |
| `HOST` | `127.0.0.1` | адрес прослушивания; наружу отдаёт только Caddy |
| `DATA_DIR` | `./data` | где лежат `cache.json`, `dividends.json`, `indices.json`, `universe.json`, `crawler-state.json`, `questions.json`, `forum.json` |
| `SITE_URL` | не задано | публичный адрес; от него зависят canonical, sitemap и флаг `Secure` у куки |
| `MAX_GENERATIONS_PER_IP_HOUR` | `40` | лимит на IP: общий для генераций, вопросов и обсуждений |
| `FORUM_ENABLED` | `1` | выключает обсуждения целиком (`0` — блок не рендерится) |
| `FORUM_MODERATOR_TOKEN` | не задано | токен для `POST /forum/hide`; без него модерация отвечает 403 |
| `MAX_FORUM_POSTS_PER_IP_HOUR` | `12` | лимит сообщений на IP, отдельное ведро от генераций |

Кеш лежит в `data/cache.json` и переживает перезапуск.

## Источники

Google News с серверных IP закрыт, `t.me` тоже не отвечает, поэтому используется то, что реально отдаёт данные без прокси:

| Источник | Что даёт | Когда используется |
|---|---|---|
| Bing News RSS | новости на русском и английском | всегда |
| Yahoo Finance RSS | новости по тикерам США и крипты | акции США, крипта |
| Reddit search RSS | посты и обсуждения | акции США, крипта |
| Финам RSS | новости компаний РФ | акции MOEX |
| Smart-Lab RSS | блоги частных инвесторов РФ | акции MOEX |
| MOEX ISS | официальные новости биржи | акции MOEX |
| dohod.ru | дивиденды по российским бумагам | блок дивидендов |
| stockanalysis.com | дивиденды по бумагам США | блок дивидендов |
| MOEX ISS (индексы) | значение, капитализация и веса бумаг | страницы индексов |
| CNBC quote / charts | значение, годовой диапазон и история индексов США | страницы индексов |

Источники опрашиваются параллельно: если один упал или не ответил, саммари всё равно собирается из остальных, а упавшие показываются в блоке «Не ответили источники». Все запросы идут с браузерным `User-Agent` — без него часть источников режет серверные IP.

Поиск тикеров: MOEX ISS (`iss/securities.json`) для российских бумаг, Yahoo Finance (`v1/finance/search`) для США и крипты. Оба опрашиваются параллельно, результаты объединяются.

## API

| Метод | Назначение |
|---|---|
| `GET /api/search?q=apple` | поиск тикеров по названию или тикеру |
| `GET /api/summary?symbol=AAPL&name=Apple&market=US` | саммари; `market` = `US` \| `RU` \| `CRYPTO`, `refresh=1` — мимо кеша |
| `GET /api/cache` | список тикеров в кеше (для чипов на главной) |
| `GET /api/status` | состояние: размер кеша, лимиты, статистика крона |
| `GET /api/health` | краткий статус |
| `POST /ticker/<market>/<symbol>/ask` | задать вопрос по тикеру; отвечает 303 на `/q/…` |
| `POST /ticker/<market>/<symbol>/thread` | открыть тему обсуждения по тикеру (нужна фраза) |
| `POST /ticker/<market>/<symbol>/forum/<id>/reply` | ответить в ветку |
| `POST /forum/hide?id=N` | скрыть сообщение, нужен `x-admin-token` |
| `GET /sitemap.xml` | карта сайта: тикеры, вопросы, темы обсуждений |
| `GET /dividends` | календарь дивидендов: ближайшие отсечки и доходность |

Ответ `/api/summary`:

```json
{
  "asset": { "symbol": "AAPL", "name": "Apple", "market": "US" },
  "summary": {
    "sentiment": "mixed",
    "headline": "…",
    "overview": "…",
    "key_points": [{ "text": "…", "refs": [1, 4] }],
    "risks": ["…"],
    "catalysts": ["…"],
    "community": "…",
    "confidence": "medium"
  },
  "news": [{ "title": "…", "link": "…", "source": "…", "published": "…", "snippet": "…" }],
  "sources": ["Bing News", "Yahoo Finance", "Reddit"],
  "warnings": [],
  "cached": false,
  "generatedAt": "…",
  "expiresAt": "…",
  "windowHours": 72
}
```

`refs` в `key_points` — номера публикаций из массива `news`, во фронтенде они кликабельны и раскрывают список источников.

## Вопросы к ИИ-аналитику

Любой посетитель может задать вопрос по тикеру. Вопрос и ответ становятся публичной страницей `/q/<market>/<symbol>/<hash>-<slug>` — она отдаётся в `sitemap.xml` и размечена как `QAPage`, потому что уникальный текст с источниками поисковики любят больше всего.

- Форма на странице тикера постит на `POST /ticker/<market>/<symbol>/ask` и отвечает 303 на страницу ответа, так что работает без JS.
- Тот же вопрос по тому же тикеру второй раз не оплачивается: сравнивается нормализованный текст, хеш становится префиксом `id`.
- Сервер проверяет только структуру: длину (12–300 символов) и наличие букв. Это дешевле, чем спрашивать модель.
- Хранится в `data/questions.json`, отдельно от `cache.json`: ответы переживают перезапуск и не раздувают кеш саммари.

**Один вызов решает всё.** Тема, мат и спам — не отдельная проверка, а поле `verdict` в том же ответе модели: `ok`, `off_topic`, `profanity`, `spam`. Модель и так видит вопрос целиком, поэтому второй запрос стоил бы вторых денег и решал бы ту же задачу по обрезанному контексту. Регэксп на мат убран: он ловил буквы, а не смысл, и пропускал и латиницу, и `бл#ть`, и разбитое пробелами. Если вердикт не `ok`, страница не публикуется, а посетитель получает текст из `VERDICT_MESSAGE` — свой для каждой причины.

Цена такой схемы: посторонний вопрос теперь оплачивает полный поисковый ответ, прежде чем получить отказ. Единственный ограничитель — общий с генерациями лимит на IP (`MAX_GENERATIONS_PER_IP_HOUR`), 40 запросов в час худшем случае ≈ $17 в сутки.

**Заголовок пишет модель.** Вопрос посетителя не попадает в `<title>`, H1, JSON-LD и slug: там оказывается переписанный по смыслу заголовок («скока дивов ждать??» → «Дивиденды Газпрома по итогам 2026 года»). Проверка `titleProblem` отбраковывает слишком короткие, слишком длинные и содержащие разметку заголовки, `fallbackTitle` подставляет обрезанный вопрос с тикером. Сам вопрос показывается на странице цитатой в `.qa-asked`.

**Откуда модель берёт данные.** Есть два режима, переключаются `QA_SEARCH_MODEL`:

| Режим | Модель | Источник фактов | Цена ответа |
|---|---|---|---|
| `web` (по умолчанию) | `sonar-pro` (Perplexity) | поиск в интернете, 15–35 цитат | ~$0.014–0.021 |
| `cache` | `MODEL` (`claude-haiku-5.5`) | только `news` из кеша по тикеру | ~$0.0008 |

Поисковая модель возвращает источники отдельным полем `annotations` — это готовые URL, их не надо угадывать, и они попадают на страницу блоком «Источники». Номера вида `[3]` в тексте размечаются ссылками на эти якоря. `search_recency_filter` (`QA_SEARCH_RECENCY`, по умолчанию `month`) не даёт Perplexity приносить прошлогодние статьи.

Цена выросла против первых замеров: на живых вопросах 2 ноября выходило $0.013–0.021 за ответ при 13–21 с на запрос, а самые длинные ответы с 15 цитатами доходили до $0.0196.

Поиска у Gemini через BotHub нет: `tools:[{google_search:{}}]` провайдер игнорирует, модель отвечает «не имею доступа к интернету». `gpt-*` с `tools:[{type:"web_search"}]` работает, но вливает в промпт 30–47k токенов, и `reasoning_tokens` съедают `max_tokens` — при 800 токенах контент приходит пустым.

Если поисковый ответ не удался или вернул меньше 40 символов, а `QA_FALLBACK_TO_CACHE=1`, вопрос молча отвечается по кешу: ответ по публикациям лучше, чем ошибка посетителю. Режим и модель записываются в запись (`mode`, `model`), поэтому страница сама подписывается «по открытым источникам» или «по публикациям за 72 ч».

## Обсуждения по тикерам

Отдельного форума нет: ветки принадлежат тикеру и живут на его странице, под сводкой и вопросами аналитику. Тем кто пришёл за бумагой, не нужно уходить в другой раздел, а обсуждение не отрывается от данных, о которых в нём спорят.

- Адреса: `/ticker/<market>/<symbol>` — дерево сообщений и форма новой темы, `/ticker/<market>/<symbol>/forum/<id>` — тема с ответами. У каждого ответа есть якорь `#m<id>` для ссылки на конкретное сообщение.
- **Дерево, а не список тем.** Строка темы, под ней с отступом её ответы, ответ на ответ — глубже. В скобках — просмотры сообщения; ноль виден прочерком, по нему понятно, что открывать нечего. Пустое сообщение (без текста) рисуется без ссылки: открывать в нём нечего.
- **Глубина считается по цепочке родителей** и никогда не читается из записи. В старых ответах поле `depth` было равно 0, и вся ветка рисовалась плоско; теперь оно не пишется вовсе. Отступ ограничен тремя уровнями, шаг задаёт CSS (`--d`), на телефоне он меньше.
- Ссылка «ответить» под сообщением ведёт на `?to=<id>#reply`: форма ответа при этом раскрыта и уже нацелена на это сообщение. Адресат не теряется ни при ошибке проверки, ни при входе по фразе — он едет в `next`.
- Просмотр засчитывается сообщению, на которое пришли (`?view=<id>`). Это отдельный параметр от `?to=<id>`, который открывает форму ответа: пришли читать — не то же самое, что пришли отвечать. Просмотры сбрасываются на диск раз в 15 секунд, при рестарте теряется не больше.
- `POST /ticker/<market>/<symbol>/thread` создаёт тему, `POST /ticker/<market>/<symbol>/forum/<id>/reply` добавляет ответ. Тема открывается только на своём тикере: чужой id в адресе даёт 404.
- `/forum` больше не раздел, а редирект в каталог. Служебные страницы остались прежними: `/forum/rules`, `/forum/login`, `/forum/register`, `/forum/me`, `/forum/logout`, `/forum/nick`. Старые ссылки `/forum/<id>` отвечают 301 на новый адрес темы.
- `data/forum.json` — аккаунты и сообщения, запись атомарная (временный файл + `rename`), с дебаунсом 60 мс, потолок `MAX_MESSAGES = 20000`.

**Вход по фразе.** Пароля и почты нет: аккаунт выводится из фразы BIP39 (12–24 слова), как в MetaMask. Сервер хранит `pbkdf2(phrase, 'mnemonic'+TAG, 2048)` → `key` и `address`, саму фразу — никогда. Соль-пароль отличается от кошельковой, поэтому фраза от настоящего кошелька даст другую идентичность. Сессия — HMAC-кука `bd_session` (`HttpOnly`, `SameSite=Lax`, `Secure` при https), секрет в `data/forum-secret.key` (0600).

**Подпись автора.** Рядом с ником показывается хостнейм отправителя: PTR-запрос с таймаутом 1.2 с и кешем на 6 часов. Полный IP не публикуется — если обратная зона не отвечает, видна только маска (`192.0.2.*`), для приватных адресов — `localhost`.

**Защита.** Ханипот `website`, `SPAM`-регэксп, длины (заголовок 4–110, текст 2–4000), `MAX_FORUM_POSTS_PER_IP_HOUR` (12, отдельное ведро от генераций), валидация `parent` внутри ветки, `safeNext` не пускает `//evil.com`. Ссылки в тексте не превращаются в разметку автоматически — это главный путь для спама мимо фильтра. Модерация: `POST /forum/hide?id=N` с заголовком `x-admin-token` (значение `FORUM_MODERATOR_TOKEN` из `.env`); скрытая тема отдаёт 404 и уходит из карты сайта.

**Оформление** — то же, что у всего сайта: `--card`, `--border`, `--accent`, системный шрифт, `.card`/`.btn`/`.qa-item`. Классов `bd-*` от прежней вёрстки не осталось.

## Как считается саммари

1. Публикации собираются параллельно из всех источников под тикер, дедуплицируются по заголовку и фильтруются по окну `NEWS_WINDOW_HOURS`.
2. Отбираются последние `MAX_NEWS` штук после фильтра релевантности (см. ниже).
3. Промпт требует строгий JSON и запрещает выдумывать факты, которых нет в подборке; посты Reddit помечены как мнения, а не факты.
4. Ответ запрашивается через `response_format: json_schema` со строгой схемой, поэтому модель физически не может вернуть обёрнутый в markdown или обрезанный JSON. На случай, если провайдер проигнорирует схему, остаётся `parseLooseJson`: он снимает обёртку и достраивает закрывающие скобки.
5. Структура ответа проверяется перед записью в кеш. Невалидный ответ не кешируется (одна повторная попытка, потом 502), а битые записи из старого `cache.json` выбрасываются при загрузке.
6. Результат кладётся в кеш на `CACHE_TTL_HOURS`.

Публикации фильтруются по релевантности до вызова модели: в тексте должны быть все значимые слова названия или сам тикер. Сравнение идёт по границам слов, поэтому `Rain` не совпадает с `training`. Для крипты дополнительно требуется крипто-контекст в публикации — иначе монета с обычным названием (`Rain`, `Gram`, `Sky`) собирает прогнозы погоды и посты не по теме.

Если релевантных публикаций меньше `MIN_NEWS` — вернётся 404 с понятным текстом, а модель не вызывается вовсе: «данных нет» она напишет и так, а деньги за это спишутся.

## Ежедневный обход

Раз в сутки (`CRAWLER_INTERVAL_HOURS`) крон обновляет саммари по фиксированному списку тикеров — посетителю ничего нажимать не нужно.

- **Список** собирается из трёх источников и пересобирается раз в сутки: индекс Мосбиржи IMOEX (41 бумага, привилегированные не дублируются), скринер Nasdaq по капитализации (~115 бумаг США), топ CoinGecko (50 монет после отбрасывания стейблкоинов, обёрнутых версий и тонких рынков). Итого ~206 тикеров.
- **Названия** чистятся от юридических форм, «Common Stock», «ао/ап» и биржевых сокращений — по названию ищутся новости, и «NVIDIA Corporation Common Stock» даёт заметно худшую выдачу, чем «NVIDIA».
- Обновление идёт с ограничением параллельности (`CRAWLER_CONCURRENCY`) и паузой между тикерами (`CRAWLER_GAP_MS`); полный проход занимает 40–60 минут.
- Тикер, который обновил посетитель, крон второй раз в тот же день не трогает.
- **Тонкие тикеры.** Если по тикеру два обхода подряд не нашлось публикаций, он выпадает из ротации, чтобы не платить за ежедневное «новостей нет». Счётчики лежат в `data/crawler-state.json` и переживают перезапуск; как только тикер открывает человек, он возвращается в ротацию.
- Файлы `universe.json` и `crawler-state.json` подхватываются на старте, поэтому после перезапуска сайт не ждёт сеть, а крон не теряет историю.

Первый полный обход на живом сервисе (2 ноября): 206 тикеров в списке, 141 саммари собрано, 16 отказов, 49 уже были в кеше, ~30 минут. Итоговое покрытие — 195 из 206 (RU 39/41, США 115/115, крипта 41/50); остальные — «тонкие» тикеры без публикаций.

Стоимость по данным API: $0.146 на 141 саммари, медиана 3.2 тыс. токенов. Полный обход ≈ **$0.16 в сутки**, то есть ~$4.8 в месяц. Отказы (404 до вызова модели) не стоят ничего — именно поэтому `MIN_NEWS` и фильтр релевантности важны: без них те же 16 тикеров съедали бы деньги на ответ «новостей нет».

## Дивиденды

Помимо новостной сводки у каждой бумаги есть блок дивидендов, а на `/dividends` — общий календарь. Модель здесь не участвует: это справочные данные из двух бесплатных источников, поэтому они не проходят через `cache.json` и не стоят денег.

- **Российские бумаги — dohod.ru** (`/ik/analytics/dividend/<тикер>`): доходность, доля от прибыли, индекс устойчивости DSI, суммы по годам и история выплат с датой закрытия реестра. Мосбиржа дивиденды в открытом доступе не отдаёт: `/iss/securities/<тикер>/dividends.json` содержит только описание бумаги, а `/iss/cci/corp-actions/dividends` закрыт подпиской.
- **Американские — stockanalysis.com.** Nasdaq для этого не годится: его API отдаёт дивиденды только по своим бумагам, а у NYSE-эмитентов (JNJ, KO, XOM, T) на тот же запрос приходит `yield: "N/A"`, хотя они платят десятилетиями. stockanalysis покрывает обе биржи и прямо говорит, когда компания не платила никогда — это отличает неплательщика от сбоя.

Разбор устойчив к тому, что dohod помечает будущие строки `class="forecast"`, но смешивает в них два разных случая: «рекомендовано советом директоров» (решение есть) и «прогноз» (решения ещё нет). Размер `0` в прогнозной строке означает «выплат не ждём», а не нулевой дивиденд. Ближайшая отсечка ищется по возрастанию даты — история отсортирована от новых к старым, и первый подходящий элемент был бы самой далёкой датой.

Обход отдельный от новостного: свой файл `data/dividends.json`, свой таймер (`DIVIDENDS_INTERVAL_HOURS`, по умолчанию сутки), пауза 300 мс между запросами. Полный проход по 156 бумагам — около 80 секунд. Покрытие: RU 39 из 41 (у `VKCO` и `UGLD` данных нет), США 100 платят и 13 не платят.

Страница бумаги получает блок только при наличии данных, поэтому у крипты и у бумаг без ответа источника его просто нет — вместо пустой таблицы. Если дивиденды есть, в `<title>` и `<h1>` добавляется слово «дивиденды»: это заметный запрос («дивиденды ВТБ» — 2,6 тыс/мес).

## Индексы

Отдельный раздел `/indices` и страница на каждый индекс: `/index/imoex`, `/index/rts`, `/index/moexbc`, `/index/rgbia`, `/index/sp500`, `/index/nasdaq`, `/index/dowjones`, `/index/vix`. Модель не участвует, данные бесплатные, поэтому у раздела свой файл `data/indices.json` и свой таймер, как у дивидендов.

- **Российские индексы — MOEX ISS.** Один запрос `engines/stock/markets/index/securities.json?securities=IMOEX,RTSI,MOEXBC,RGBI` отдаёт значение, изменение за день, месяц и год, максимум и минимум дня и капитализацию. История — `history/.../securities/IMOEX.json`, состав с весами — `statistics/.../analytics/IMOEX.json`.
- **Американские — CNBC.** `quote.cnbc.com/.../restQuote/symbolType/symbol?symbols=.SPX|.DJI|.IXIC|.VIX` отдаёт все четыре одним запросом вместе с предыдущим закрытием и годовым диапазоном; `ts-api.cnbc.com/harmony/app/charts/1Y.json` — история за два года. Nasdaq знает только свой Composite, а Yahoo режет по 429 при частых запросах, поэтому оба отклонены.
- **Свои коды ≠ биржевые.** У нас `SP500`, `NASDAQ`, `DOW`, `VIX`, у CNBC — `.SPX`, `.IXIC`, `.DJI`, `.VIX`. Ключ хранилища — наш код, иначе значение не найдётся на странице.
- **Годовое изменение считается по-разному.** Мосбиржа присылает его готовым, CNBC — нет; там оно считается по своей истории как ближайшая точка за год до последней. Если ряд короче года больше чем на 45 дней, выводится прочерк, а не цифра за полгода.
- **IMOEX и RGBI — ценовые индексы.** Дивиденды и купоны в их значение не входят: за доходность с реинвестированием отвечают отдельные MCFTR и RGBITR. На страницах это сказано прямо, иначе «индекс полной доходности» был бы ошибкой.
- **История Мосбиржи — окно 365 дней.** Биржа отдаёт не более 100 строк на страницу, поэтому год собирается тремя запросами. При окне 250 дней ряд обрывался на восьмом месяце, хотя страница обещает динамику за год.
- **График — свой SVG** по точкам истории. Клиентский JS поисковик не исполняет, а картинка со стороны — лишняя зависимость. Значения частые (5 минут), история и состав — раз в сутки: они не меняются.
- **Страницы закрыты, пока нет данных.** `/indices` и `/index/*` отдают 404, пока крон не сохранил первое значение, и до этого же не попадают в `sitemap.xml` — как у дивидендов, пустая страница из прочерков не индексируется.
- **Названия в составе чистятся** теми же `cleanRuName` / `RU_ALIASES`, что и каталог: биржа отдаёт «ГАЗПРОМ ао» и «Татнфт 3ао». Ссылками становятся только те бумаги, у которых есть страница на сайте.

## Графики цен

На каждой странице тикера — график за год по дневным закрытиям. Модель не участвует, данные бесплатные, поэтому у графиков свой файл `data/charts.json` и свой таймер, как у дивидендов и индексов.

- **Россия — MOEX ISS, свечи.** `/iss/engines/stock/markets/shares/securities/<тикер>/candles.json?interval=24&from=…&till=…&limit=500` отдаёт весь год одним запросом (334 свечи по Газпрому), тогда как эндпоинт `history` режет ответ сотней строк и требует шести страниц. Все 41 бумага собираются за 12 секунд.
- **США — CNBC.** `ts-api.cnbc.com/harmony/app/charts/1Y.json?symbol=<тикер>&interval=1D` даёт ~500 дневных баров, покрывает и NYSE, и Nasdaq. У `BRK-A` в каталоге дефис, а CNBC знает `BRK.A`: варианты перебираются по очереди.
- **Крипта — Binance, а CoinGecko только как запасной.** `api.binance.com/api/v3/klines?symbol=<тикер>USDT&interval=1d&limit=366` — 366 свечей одним запросом, без ключа и без лимитов; так закрываются 39 монет из 50. Остальные (биржевые токены `WBT`, `OKB`, `BGB`, `MNT`, `GT`, `KCS`) идут через CoinGecko `coins/<id>/market_chart?days=365&interval=daily`. Yahoo первым не годится: под `POL` он отдаёт DOT, а `HYPE`, `RAIN`, `CC`, `PUMP` не находит вовсе.
- **Пары Binance сверяются по цене.** Совпадение символа не значит совпадение монеты: под `XMR` на Binance торгуется не Monero за $610, а другой токен за $118. Последняя цена пары сравнивается с ценой CoinGecko из того же запроса, что даёт id; расхождение больше 20% — монета уходит на CoinGecko.
- **CoinGecko отвечает 429 непредсказуемо.** На бесплатном тарифе он считает запросы в минуту: при паузе 1,5 с отказывал на каждой второй монете, при 4 с — на девятой из пятидесяти. Поэтому он не первый источник, а второй, и на отказе делается один повтор.
- **График — серверный inline SVG.** Как у индексов: клиентский JS поисковик не исполняет, а внешняя картинка — лишняя зависимость. Точки прореживаются до ~150 перед отрисовкой (год — это 250–500 точек), но глобальный минимум и максимум остаются всегда, иначе пик мог бы попасть между выборками.
- **Периоды — обычные ссылки** `?period=1m|3m|6m|1y`, по умолчанию год. Канонический адрес — страница без параметра: иначе поисковик увидел бы четыре копии одной страницы.
- **Под графиком — таблица помесячных закрытий** в `<details>`. Поисковику текст полезнее ломаной, а человеку даёт точные цифры.
- **Нет истории — нет блока.** Как у дивидендов: пустая рамка «данные ещё не собраны» на каждой новой бумаге выглядит как поломка. Ссылка «График» в верхнем меню страницы появляется вместе с блоком.
- **Последняя точка — итог последнего торгового дня,** а не котировка в реальном времени. Это сказано подписью под блоком, чтобы «цена» не читалась как тик.

### Защита от чужих запросов

Порт открыт в интернет, а каждый новый тикер — это платный вызов модели. Два предохранителя:

- **Лимит генераций:** не больше `MAX_GENERATIONS_PER_HOUR` (по умолчанию 40) новых саммари в час на весь процесс. Попадания в кеш лимит не тратят. При превышении — 429 с понятным текстом.
- **Basic-авторизация:** задайте в `.env` строку `BASIC_AUTH=user:password` и перезапустите сервис — тогда весь сайт и API попросят пароль. Проверено: без пароля 401, с паролем 200.

`.env` не публикуется как статика (страницы отдаются только из `public/`), ключ BotHub в браузер не попадает.
