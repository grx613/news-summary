# $BOTHUB Аналитика

Сервис: вводите название компании или криптовалюты (по названию либо по тикеру) — получаете AI-саммари свежих публикаций по этому активу.

- Поиск работает по названию и тикеру: `Apple`, `AAPL`, `Bitcoin`, `BTC`, `Газпром`, `GAZP`, `Сбербанк`, `SBER`.
- Поддерживаются три рынка: акции MOEX, акции США, криптовалюты.
- **Кеширование:** первый запрос по тикеру идёт в источники и к модели (10–40 с), повторный — мгновенно из кеша. TTL 26 часов: раз в сутки все тикеры обновляет фоновый крон, так что посетитель почти всегда попадает в кеш.
- **Кнопка «Обновить»** пересобирает саммари мимо кеша, но не чаще раза в 15 минут на тикер — ограничение общее для всех посетителей, кнопка показывает обратный отсчёт.
- Саммари генерирует `claude-haiku-5.5` через OpenAI-совместимый API BotHub.
- По каждому тикеру можно задать вопрос — отвечает ИИ-аналитик. По умолчанию он ищет данные в интернете (`sonar-pro`, Perplexity) и показывает список источников; вопрос с ответом публикуется отдельной страницей.
- **Дивиденды:** на странице каждой бумаги — история выплат, дата закрытия реестра, доходность и суммы по годам; на `/dividends` — календарь ближайших отсечек. Данные бесплатные, модель не вызывается.

## Запуск

```bash
git clone https://github.com/grx613/news-summary.git
cd news-summary
cp .env.example .env    # и вписать BOTHUB_API_KEY
node server.js
# http://localhost:3000
```

Node.js 18+ (нужен встроенный `fetch`). Зависимостей нет — только стандартная библиотека.

`.env` и весь `data/` в репозиторий не попадают: там ключ BotHub, кеш саммари, вопросы и обсуждения. Полный список переменных с умолчаниями — в `.env.example`. Настройки в `.env`:

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `BOTHUB_API_KEY` | — | ключ BotHub (обязателен) |

| `MAX_NEWS` | `30` | сколько публикаций уходит в модель |
| `MIN_NEWS` | `3` | минимум релевантных публикаций; меньше — 404 без вызова модели |
| `REDDIT_MIN_GAP_MS` | `3000` | пауза между запросами к Reddit (иначе 429) |
| `BASIC_AUTH` | не задано | `user:password` — включить пароль на весь сайт и API |
| `MAX_GENERATIONS_PER_HOUR` | `40` | потолок новых генераций в час по запросам пользователей (крон не считается) |

| `DIVIDENDS_INTERVAL_HOURS` | `24` | как часто обновляются дивиденды |
| `INDICES_ENABLED` | `1` | сбор значений индексов (`0` — не ходить на Мосбиржу и в CNBC) |
| `INDICES_QUOTE_MIN` | `5` | как часто обновляются значения индексов, в минутах |

| `DATA_DIR` | `./data` | где лежат `cache.json`, `dividends.json`, `indices.json`, `universe.json`, `crawler-state.json`, `questions.json`, `forum.json` |
| `SITE_URL` | не задано | публичный адрес; от него зависят canonical, sitemap и флаг `Secure` у куки |

Кеш лежит в `data/cache.json` и переживает перезапуск.

## Источники

Google News с серверных IP закрыт, `t.me` тоже не отвечает, поэтому используется то, что реально отдаёт данные без прокси:

| Источник | Что даёт | Когда используется |
|---|---|---|
| Bing News RSS | новости на русском и английском | всегда |
| Yahoo Finance RSS | новости по тикерам США и крипты | акции США, крипта |
| Reddit search RSS | посты и обсуждения | акции США, крипта |
| Финам RSS | новости компаний РФ | акции MOEX |
| Smart-Lab RSS | блоги частных инвесторов РФ | акции MOEX |
| MOEX ISS | официальные новости биржи | акции MOEX |
| dohod.ru | дивиденды по российским бумагам | блок дивидендов |
| stockanalysis.com | дивиденды по бумагам США | блок дивидендов |
| MOEX ISS (индексы) | значение, капитализация и веса бумаг | страницы индексов |
| CNBC quote / charts | значение, годовой диапазон и история индексов США | страницы индексов |

Источники опрашиваются параллельно: если один упал или не ответил, саммари всё равно собирается из остальных, а упавшие показываются в блоке «Не ответили источники». Все запросы идут с браузерным `User-Agent` — без него часть источников режет серверные IP.

Поиск тикеров: MOEX ISS (`iss/securities.json`) для российских бумаг, Yahoo Finance (`v1/finance/search`) для США и крипты. Оба опрашиваются параллельно, результаты объединяются.

## API

| Метод | Назначение |
|---|---|
| `GET /api/search?q=apple` | поиск тикеров по названию или тикеру |
| `GET /api/summary?symbol=AAPL&name=Apple&market=US` | саммари; `market` = `US` \| `RU` \| `CRYPTO`, `refresh=1` — мимо кеша |
| `GET /api/cache` | список тикеров в кеше (для чипов на главной) |
| `GET /?tab=us` | главная с вкладкой: `us`, `ru`, `crypto`; без параметра — все рынки |
| `GET /api/status` | состояние: размер кеша, лимиты, статистика крона |
| `GET /api/health` | краткий статус |
| `POST /ticker/<market>/<symbol>/ask` | задать вопрос по тикеру; отвечает 303 на `/q/…` |
| `POST /ticker/<market>/<symbol>/thread` | открыть тему обсуждения по тикеру (нужна фраза) |
| `POST /ticker/<market>/<symbol>/forum/<id>/reply` | ответить в ветку |
| `POST /forum/hide?id=N` | скрыть сообщение, нужен `x-admin-token` |
| `GET /sitemap.xml` | карта сайта: тикеры, вопросы, темы обсуждений |
| `GET /dividends` | календарь дивидендов: ближайшие отсечки и доходность |

Ответ `/api/summary`:

```json
{
  "asset": { "symbol": "AAPL", "name": "Apple", "market": "US" },
  "summary": {
    "sentiment": "mixed",
    "headline": "…",
    "overview": "…",
    "key_points": [{ "text": "…", "refs": [1, 4] }],
    "risks": ["…"],
    "catalysts": ["…"],
    "community": "…",
    "confidence": "medium"
  },
  "news": [{ "title": "…", "link": "…", "source": "…", "published": "…", "snippet": "…" }],
  "sources": ["Bing News", "Yahoo Finance", "Reddit"],
  "warnings": [],
  "cached": false,
  "generatedAt": "…",
  "expiresAt": "…",
  "windowHours": 72
}
```

`refs` в `key_points` — номера публикаций из массива `news`, во фронтенде они кликабельны и раскрывают список источников.

## Вопросы к ИИ-аналитику

Любой посетитель может задать вопрос по тикеру. Вопрос и ответ становятся публичной страницей `/q/<market>/<symbol>/<hash>-<slug>` — она отдаётся в `sitemap.xml` и размечена как `QAPage`, потому что уникальный текст с источниками поисковики любят больше всего.

- Форма на странице тикера постит на `POST /ticker/<market>/<symbol>/ask` и отвечает 303 на страницу ответа, так что работает без JS.
- Тот же вопрос по тому же тикеру второй раз не оплачивается: сравнивается нормализованный текст, хеш становится префиксом `id`.
- Сервер проверяет только структуру: длину (12–300 символов) и наличие букв. Это дешевле, чем спрашивать модель.
- Хранится в `data/questions.json`, отдельно от `cache.json`: ответы переживают перезапуск и не раздувают кеш саммари.

**Один вызов решает всё.** Тема, мат и спам — не отдельная проверка, а поле `verdict` в том же ответе модели: `ok`, `off_topic`, `profanity`, `spam`. Модель и так видит вопрос целиком, поэтому второй запрос стоил бы вторых денег и решал бы ту же задачу по обрезанному контексту. Регэксп на мат убран: он ловил буквы, а не смысл, и пропускал и латиницу, и `бл#ть`, и разбитое пробелами. Если вердикт не `ok`, страница не публикуется, а посетитель получает текст из `VERDICT_MESSAGE` — свой для каждой причины.

Цена такой схемы: посторонний вопрос теперь оплачивает полный поисковый ответ, прежде чем получить отказ. Единственный ограничитель — общий с генерациями лимит на IP (`MAX_GENERATIONS_PER_IP_HOUR`), 40 запросов в час худшем случае ≈ $17 в сутки.

**Заголовок пишет модель.** Вопрос посетителя не попадает в `<title>`, H1, JSON-LD и slug: там оказывается переписанный по смыслу заголовок («скока дивов ждать??» → «Дивиденды Газпрома по итогам 2026 года»). Проверка `titleProblem` отбраковывает слишком короткие, слишком длинные и содержащие разметку заголовки, `fallbackTitle` подставляет обрезанный вопрос с тикером. Сам вопрос показывается на странице цитатой в `.qa-asked`.

**Откуда модель берёт данные.** Есть два режима, переключаются `QA_SEARCH_MODEL`:

| Режим | Модель | Источник фактов | Цена ответа |
|---|---|---|---|
| `web` (по умолчанию) | `sonar-pro` (Perplexity) | поиск в интернете, 15–35 цитат | ~$0.014–0.021 |
| `cache` | `MODEL` (`claude-haiku-5.5`) | только `news` из кеша по тикеру | ~$0.0008 |

Поисковая модель возвращает источники отдельным полем `annotations` — это готовые URL, их не надо угадывать, и они попадают на страницу блоком «Источники». Номера вида `[3]` в тексте размечаются ссылками на эти якоря. `search_recency_filter` (`QA_SEARCH_RECENCY`, по умолчанию `month`) не даёт Perplexity приносить прошлогодние статьи.

Цена выросла против первых замеров: на живых вопросах 2 ноября выходило $0.013–0.021 за ответ при 13–21 с на запрос, а самые длинные ответы с 15 цитатами доходили до $0.0196.

**Дорогие модели.** `sonar-deep-research` стоит 345 ₽ за миллион входных токенов и 1380 ₽ за миллион выходных — против 17 и 86 у `claude-haiku-5.5`. Один случайный вызов 2 ноября (400 токенов вывода) обошёлся в 67,5 ₽, то есть в четверть всего расхода проекта за первые три дня. Поэтому в `server.js` есть список `EXPENSIVE_MODELS`: и `MODEL`, и `QA_SEARCH_MODEL` проходят через `safeModel()`, а `callModel()` проверяет модель ещё раз перед запросом. Дорогое имя в `.env` не роняет сервис — печатается предупреждение, подставляется `sonar-pro` (или `claude-haiku-5.5` для `MODEL`). Список пополняется в одном месте, а не в каждом вызове.

Поиска у Gemini через BotHub нет: `tools:[{google_search:{}}]` провайдер игнорирует, модель отвечает «не имею доступа к интернету». `gpt-*` с `tools:[{type:"web_search"}]` работает, но вливает в промпт 30–47k токенов, и `reasoning_tokens` съедают `max_tokens` — при 800 токенах контент приходит пустым.

Если поисковый ответ не удался или вернул меньше 40 символов, а `QA_FALLBACK_TO_CACHE=1`, вопрос молча отвечается по кешу: ответ по публикациям лучше, чем ошибка посетителю. Режим и модель записываются в запись (`mode`, `model`), поэтому страница сама подписывается «по открытым источникам» или «по публикациям за 72 ч».

## Обсуждения по тикерам

Отдельного форума нет: ветки принадлежат тикеру и живут на его странице, под сводкой и вопросами аналитику. Тем кто пришёл за бумагой, не нужно уходить в другой раздел, а обсуждение не отрывается от данных, о которых в нём спорят.

Раздел называется «Форум акции Сбербанк (SBER)» — не «обсуждение». Слово «форум» ищут, оно же стоит в `<title>` страницы ветки, в главном меню пункт тоже называется «Форум». Формулировка с родительным падежом («Форум акций») читается как название раздела сайта, а не форума одной бумаги, поэтому у акции родительный единственный, у монеты — «Форум монеты».

- Адреса: `/ticker/<market>/<symbol>` — дерево сообщений и форма новой темы, `/ticker/<market>/<symbol>/forum/<id>` — тема с ответами. У каждого ответа есть якорь `#m<id>` для ссылки на конкретное сообщение.
- **Дерево, а не список тем.** Строка темы, под ней с отступом её ответы, ответ на ответ — глубже. В скобках — просмотры сообщения; ноль виден прочерком, по нему понятно, что открывать нечего. Пустое сообщение (без текста) рисуется без ссылки: открывать в нём нечего.
- **Глубина считается по цепочке родителей** и никогда не читается из записи. В старых ответах поле `depth` было равно 0, и вся ветка рисовалась плоско; теперь оно не пишется вовсе. Отступ ограничен тремя уровнями, шаг задаёт CSS (`--d`), на телефоне он меньше.
- Ссылка «ответить» под сообщением ведёт на `?to=<id>#reply`: форма ответа при этом раскрыта и уже нацелена на это сообщение. Адресат не теряется ни при ошибке проверки, ни при входе по фразе — он едет в `next`.
- Просмотр засчитывается сообщению, на которое пришли (`?view=<id>`). Это отдельный параметр от `?to=<id>`, который открывает форму ответа: пришли читать — не то же самое, что пришли отвечать. Просмотры сбрасываются на диск раз в 15 секунд, при рестарте теряется не больше.
- `POST /ticker/<market>/<symbol>/thread` создаёт тему, `POST /ticker/<market>/<symbol>/forum/<id>/reply` добавляет ответ. Тема открывается только на своём тикере: чужой id в адресе даёт 404.
- `/forum` больше не раздел, а редирект в каталог. Служебные страницы остались прежними: `/forum/rules`, `/forum/login`, `/forum/register`, `/forum/me`, `/forum/logout`, `/forum/nick`. Старые ссылки `/forum/<id>` отвечают 301 на новый адрес темы.
- `data/forum.json` — аккаунты и сообщения, запись атомарная (временный файл + `rename`), с дебаунсом 60 мс, потолок `MAX_MESSAGES = 20000`.

**Вход по фразе.** Пароля и почты нет: аккаунт выводится из фразы BIP39 (12–24 слова), как в MetaMask. Сервер хранит `pbkdf2(phrase, 'mnemonic'+TAG, 2048)` → `key` и `address`, саму фразу — никогда. Соль-пароль отличается от кошельковой, поэтому фраза от настоящего кошелька даст другую идентичность. Сессия — HMAC-кука `bd_session` (`HttpOnly`, `SameSite=Lax`, `Secure` при https), секрет в `data/forum-secret.key` (0600).

**Подпись автора.** Рядом с ником показывается хостнейм отправителя: PTR-запрос с таймаутом 1.2 с и кешем на 6 часов. Полный IP не публикуется — если обратная зона не отвечает, видна только маска (`192.0.2.*`), для приватных адресов — `localhost`.

**Защита.** Ханипот `website`, `SPAM`-регэксп, длины (заголовок 4–110, текст до 4000; пустой текст разрешён — пустая строка это законная отметка в ветке, поэтому у `<textarea>` нет `required`), `MAX_FORUM_POSTS_PER_IP_HOUR` (12, отдельное ведро от генераций), валидация `parent` внутри ветки, `safeNext` не пускает `//evil.com`. Ссылки в тексте не превращаются в разметку автоматически — это главный путь для спама мимо фильтра. Модерация: `POST /forum/hide?id=N` с заголовком `x-admin-token` (значение `FORUM_MODERATOR_TOKEN` из `.env`); скрытая тема отдаёт 404 и уходит из карты сайта.

**Оформление** — то же, что у всего сайта: `--card`, `--border`, `--accent`, системный шрифт, `.card`/`.btn`/`.qa-item`. Классов `bd-*` от прежней вёрстки не осталось.

## Главная страница

Главная — витрина, а не только поиск: под строкой поиска идёт таблица «По капитализации», как на биржевых витринах. Строка — название со ссылкой на тикер, рынок, цена закрытия последнего торгового дня, изменение за день и капитализация. Над таблицей вкладки «Все / США / Акции РФ / Крипта».

- **Вкладки — обычные ссылки** `/?tab=us`, а не клиентский фильтр. Поисковик не исполняет JS, поэтому сервер отдаёт уже отфильтрованный список, а у каждой вкладки свой `<title>`, `<h1>`, описание и канонический адрес. Неизвестное значение молча откатывается на «Все», как и неизвестный интервал свечи. В `sitemap.xml` вкладки идут отдельно от корня.
- **Каталог на вкладке показывает только её рынок.** Иначе три адреса главной несли бы одни и те же 200 ссылок и выглядели как копии друг друга.
- **Сортировка идёт по `capUsd`**, а не по числу в записи: капитализации разных валют несравнимы. Рубли переводятся по курсу USD/RUB при сборке списка (см. «Ежедневный обход»).- **Список не обрезается.** Потолок в сотню строк вырезал бы весь российский рынок: крупнейшая бумага Мосбиржи (Сбербанк) стоит в общей сортировке около 120-го места, потому что капитализация российского рынка на два порядка меньше американского. Поэтому на вкладке «Все» показаны все 210 тикеров.
- **Цена и изменение берутся из `charts.json`**, того же дневного ряда, что и график на странице тикера: отдельного запроса за котировками нет, а расхождение между таблицей и страницей исключено. Нулевое изменение рисуется нейтральным цветом — зелёный на «0,00%» врал бы о направлении.
- **Тикеры без цены не выпадают из таблицы**: строка остаётся, цена и капитализация показываются прочерком. Записи старого формата `[дата, закрытие]` проходят через `normalizePoints` и тоже дают цену.

## Как считается саммари

1. Публикации собираются параллельно из всех источников под тикер, дедуплицируются по заголовку и фильтруются по окну `NEWS_WINDOW_HOURS`.
2. Отбираются последние `MAX_NEWS` штук после фильтра релевантности (см. ниже).
3. Промпт требует строгий JSON и запрещает выдумывать факты, которых нет в подборке; посты Reddit помечены как мнения, а не факты.
4. Ответ запрашивается через `response_format: json_schema` со строгой схемой, поэтому модель физически не может вернуть обёрнутый в markdown или обрезанный JSON. На случай, если провайдер проигнорирует схему, остаётся `parseLooseJson`: он снимает обёртку и достраивает закрывающие скобки.
5. Структура ответа проверяется перед записью в кеш. Невалидный ответ не кешируется (одна повторная попытка, потом 502), а битые записи из старого `cache.json` выбрасываются при загрузке.
6. Результат кладётся в кеш на `CACHE_TTL_HOURS`.

Публикации фильтруются по релевантности до вызова модели: в тексте должны быть все значимые слова названия или сам тикер. Сравнение идёт по границам слов, поэтому `Rain` не совпадает с `training`. Для крипты дополнительно требуется крипто-контекст в публикации — иначе монета с обычным названием (`Rain`, `Gram`, `Sky`) собирает прогнозы погоды и посты не по теме.

Если релевантных публикаций меньше `MIN_NEWS` — вернётся 404 с понятным текстом, а модель не вызывается вовсе: «данных нет» она напишет и так, а деньги за это спишутся.

## Ежедневный обход

Раз в сутки (`CRAWLER_INTERVAL_HOURS`) крон обновляет саммари по фиксированному списку тикеров — посетителю ничего нажимать не нужно.

- **Список** собирается из трёх источников и пересобирается раз в сутки: индекс Мосбиржи IMOEX (41 бумага, привилегированные не дублируются), скринер Nasdaq по капитализации (~115 бумаг США), топ CoinGecko (50 монет после отбрасывания стейблкоинов, обёрнутых версий и тонких рынков). Итого ~206 тикеров.
- **Названия** чистятся от юридических форм, «Common Stock», «ао/ап» и биржевых сокращений — по названию ищутся новости, и «NVIDIA Corporation Common Stock» даёт заметно худшую выдачу, чем «NVIDIA».
- Обновление идёт с ограничением параллельности (`CRAWLER_CONCURRENCY`) и паузой между тикерами (`CRAWLER_GAP_MS`); полный проход занимает 40–60 минут.
- Тикер, который обновил посетитель, крон второй раз в тот же день не трогает.
- **Тонкие тикеры.** Если по тикеру два обхода подряд не нашлось публикаций, он выпадает из ротации на неделю (`THIN_RETRY_MS`), а не навсегда. Отказ по `MIN_NEWS` не стоит денег — модель не вызывается, — поэтому вечное исключение ничего не экономило, зато оставляло страницу со сводкой недельной давности. Счётчики и отметки времени лежат в `data/crawler-state.json` и переживают перезапуск; как только тикер открывает человек, он возвращается в ротацию сразу.
- **Отсрочка после ошибки тоже в файле.** Раньше `backoff` жил только в памяти: перезапуск его очищал, крон через минуту снова бил по тем же тикерам и второй раз засчитывал страйк за те же сутки. Несколько перезапусков 2 ноября заморозили пять тикеров после одного неудачного утра.
- **Крон обновляет по TTL, а не только по своему интервалу:** `dueAfter = min(интервал × 0,9, TTL × 0,85)`. При TTL 26 ч и интервале 24 ч оба дают 21,6 ч, но если TTL станет короче интервала, сводки протухали бы между прогонами. Текущее значение видно в `/api/status` как `crawler.dueAfterHours`.
- **В список крона входят и тикеры из кеша**, которых нет в дневном списке: привилегированные бумаги вроде `SBERP` схлопываются с обыкновенными на этапе дедупликации, но страница и запись в `sitemap.xml` у них есть. Без этого их сводка не обновлялась бы никогда.
- Файлы `universe.json` и `crawler-state.json` подхватываются на старте, поэтому после перезапуска сайт не ждёт сеть, а крон не теряет историю.
- **Капитализация** хранится в том же списке (`cap` и `capUsd`): она нужна главной, где тикеры отсортированы по капитализации. Источники отдают её по-разному. Nasdaq отдаёт готовое поле `marketCap`. CoinGecko — `market_cap`. У Мосбиржи отдельного поля нет: капитализация считается как `ISSUESIZE × PREVPRICE` из того же запроса, где берутся названия, — это полная капитализация по числу акций в выпуске, а не та, что в индексе по free-float. Рубли переводятся в доллары по биржевому курсу USD/RUB (запасной источник — ЦБ), иначе рублёвая капитализация несравнима с долларовой и «самая дорогая компания» — это просто та, у которой больше цифра. Всё это пересобирается раз в сутки вместе со списком.

Первый полный обход на живом сервисе (2 ноября): 206 тикеров в списке, 141 саммари собрано, 16 отказов, 49 уже были в кеше, ~30 минут. Итоговое покрытие — 195 из 206 (RU 39/41, США 115/115, крипта 41/50); остальные — «тонкие» тикеры без публикаций.

Стоимость по данным API: $0.146 на 141 саммари, медиана 3.2 тыс. токенов. Полный обход ≈ **$0.16 в сутки**, то есть ~$4.8 в месяц. Отказы (404 до вызова модели) не стоят ничего — именно поэтому `MIN_NEWS` и фильтр релевантности важны: без них те же 16 тикеров съедали бы деньги на ответ «новостей нет».

## Дивиденды

Помимо новостной сводки у каждой бумаги есть блок дивидендов, а на `/dividends` — общий календарь. Модель здесь не участвует: это справочные данные из двух бесплатных источников, поэтому они не проходят через `cache.json` и не стоят денег.

- **Российские бумаги — dohod.ru** (`/ik/analytics/dividend/<тикер>`): доходность, доля от прибыли, индекс устойчивости DSI, суммы по годам и история выплат с датой закрытия реестра. Мосбиржа дивиденды в открытом доступе не отдаёт: `/iss/securities/<тикер>/dividends.json` содержит только описание бумаги, а `/iss/cci/corp-actions/dividends` закрыт подпиской.
- **Американские — stockanalysis.com.** Nasdaq для этого не годится: его API отдаёт дивиденды только по своим бумагам, а у NYSE-эмитентов (JNJ, KO, XOM, T) на тот же запрос приходит `yield: "N/A"`, хотя они платят десятилетиями. stockanalysis покрывает обе биржи и прямо говорит, когда компания не платила никогда — это отличает неплательщика от сбоя.

Разбор устойчив к тому, что dohod помечает будущие строки `class="forecast"`, но смешивает в них два разных случая: «рекомендовано советом директоров» (решение есть) и «прогноз» (решения ещё нет). Размер `0` в прогнозной строке означает «выплат не ждём», а не нулевой дивиденд. Ближайшая отсечка ищется по возрастанию даты — история отсортирована от новых к старым, и первый подходящий элемент был бы самой далёкой датой.

Обход отдельный от новостного: свой файл `data/dividends.json`, свой таймер (`DIVIDENDS_INTERVAL_HOURS`, по умолчанию сутки), пауза 300 мс между запросами. Полный проход по 156 бумагам — около 80 секунд. Покрытие: RU 39 из 41 (у `VKCO` и `UGLD` данных нет), США 100 платят и 13 не платят.

Страница бумаги получает блок только при наличии данных, поэтому у крипты и у бумаг без ответа источника его просто нет — вместо пустой таблицы. Если дивиденды есть, в `<title>` и `<h1>` добавляется слово «дивиденды»: это заметный запрос («дивиденды ВТБ» — 2,6 тыс/мес).

## Индексы

Отдельный раздел `/indices` и страница на каждый индекс: `/index/imoex`, `/index/rts`, `/index/moexbc`, `/index/rgbia`, `/index/sp500`, `/index/nasdaq`, `/index/dowjones`, `/index/vix`. Модель не участвует, данные бесплатные, поэтому у раздела свой файл `data/indices.json` и свой таймер, как у дивидендов.

- **Российские индексы — MOEX ISS.** Один запрос `engines/stock/markets/index/securities.json?securities=IMOEX,RTSI,MOEXBC,RGBI` отдаёт значение, изменение за день, месяц и год, максимум и минимум дня и капитализацию. История — `history/.../securities/IMOEX.json`, состав с весами — `statistics/.../analytics/IMOEX.json`.
- **Американские — CNBC.** `quote.cnbc.com/.../restQuote/symbolType/symbol?symbols=.SPX|.DJI|.IXIC|.VIX` отдаёт все четыре одним запросом вместе с предыдущим закрытием и годовым диапазоном; `ts-api.cnbc.com/harmony/app/charts/1Y.json` — история за два года. Nasdaq знает только свой Composite, а Yahoo режет по 429 при частых запросах, поэтому оба отклонены.
- **Свои коды ≠ биржевые.** У нас `SP500`, `NASDAQ`, `DOW`, `VIX`, у CNBC — `.SPX`, `.IXIC`, `.DJI`, `.VIX`. Ключ хранилища — наш код, иначе значение не найдётся на странице.
- **Годовое изменение считается по-разному.** Мосбиржа присылает его готовым, CNBC — нет; там оно считается по своей истории как ближайшая точка за год до последней. Если ряд короче года больше чем на 45 дней, выводится прочерк, а не цифра за полгода.
- **IMOEX и RGBI — ценовые индексы.** Дивиденды и купоны в их значение не входят: за доходность с реинвестированием отвечают отдельные MCFTR и RGBITR. На страницах это сказано прямо, иначе «индекс полной доходности» был бы ошибкой.
- **История Мосбиржи — окно 365 дней.** Биржа отдаёт не более 100 строк на страницу, поэтому год собирается тремя запросами. При окне 250 дней ряд обрывался на восьмом месяце, хотя страница обещает динамику за год.
- **График — свой SVG** по точкам истории. Клиентский JS поисковик не исполняет, а картинка со стороны — лишняя зависимость. Значения частые (5 минут), история и состав — раз в сутки: они не меняются.
- **Страницы закрыты, пока нет данных.** `/indices` и `/index/*` отдают 404, пока крон не сохранил первое значение, и до этого же не попадают в `sitemap.xml` — как у дивидендов, пустая страница из прочерков не индексируется.
- **Названия в составе чистятся** теми же `cleanRuName` / `RU_ALIASES`, что и каталог: биржа отдаёт «ГАЗПРОМ ао» и «Татнфт 3ао». Ссылками становятся только те бумаги, у которых есть страница на сайте.

## Графики цен

На каждой странице тикера — **японские свечи**: интервал от минуты до месяца, окно от месяца до года. Модель не участвует, данные бесплатные, поэтому у графиков свой файл `data/charts.json` и свой таймер, как у дивидендов и индексов.

- **Свеча — `[время, open, high, low, close]`.** Дневные ряды живут в файле с датой `YYYY-MM-DD`, внутридневные — с секундами unix. Записи, собранные до перехода на OHLC, лежат парами `[дата, закрытие]`; `normalizePoints` достраивает из них свечу без тела, поэтому переход не оставил ни одной страницы без графика.
- **Внутридневные ряды не хранятся на диске.** Минутный ряд по 206 тикерам — это ~150 тысяч свечей, устаревающих к следующему показу, поэтому они запрашиваются при показе страницы и живут в памяти: 45 секунд для минуток, две минуты для остальных. Параллельные показы одной бумаги ждут один запрос (`inflight`), отказ источника отдаёт просроченный ряд вместо пустоты.
- **Россия — MOEX ISS, нативно 1, 10 и 60 минут, день, неделя, месяц.** 5 и 15 минут Мосбиржа не отдаёт (запрос с `interval=5` возвращает 0 строк), поэтому они склеиваются из минуток: 500 строк на страницу при любом `limit`, свежие данные через `iss.reverse=true`, страницы забираются параллельно — 5 минутам нужно шесть, 15 минутам двенадцать, оба меньше половины секунды. Склейка проверена на живых данных: собранные из минуток 10-минутные свечи совпали с нативными на всех 202.
- **США — Yahoo для внутри дня, CNBC для дня.** У CNBC шаг свечи не задаётся: `1D.json` всегда минутки, `5D.json` — пятиминутки, `interval=5M` игнорируется. Yahoo отдаёт 1, 5, 15, 30, 60 минут, неделю и месяц; диапазоны ограничены (`1m` только 7 дней, `15m`/`30m` только месяц), поэтому окно подбирается под интервал. CNBC остаётся запасным для минуток и пятиминуток.
- **Крипта — Binance, затем MEXC, затем Gate.io.** MEXC говорит на API Binance и закрывает почти все монеты, которых там нет (`WBT`, `OKB`, `BGB`, `KCS`, `MNT`, `HTX`, `VVV`, `RAIN`, `CC`), Gate — `GT`. Вместе они дают 50 из 50, тогда как один Binance — 39.
- **Пары сверяются по цене.** Совпадение символа не значит совпадение монеты: под `XMRUSDT` на Binance торгуется не Monero за $610, а другой токен за $118. MEXC отдаёт правильную Monero. Последняя цена пары сравнивается с ценой CoinGecko; расхождение больше 20% — биржа отвергается. Внутридневной график сверяется уже с дневным закрытием из файла, чтобы не ходить в CoinGecko на каждый показ.
- **CoinGecko — последний запасной источник.** Свечей он не отдаёт, только закрытия: open берётся от предыдущего дня, тени совпадают с телом. Он же на бесплатном тарифе отвечает 429 непредсказуемо (при паузе 4 с отказывал на девятой монете из пятидесяти), поэтому он не первый, а последний.
- **График — серверный inline SVG.** Клиентский JS поисковик не исполняет, а внешняя картинка — лишняя зависимость. Тело свечи занимает не больше 62% шага и не меньше 0,55 единицы, поэтому даже 500 свечей не сливаются в сплошную заливку. Ряд длиннее 400 свечей обрезается с начала, а не прореживается: склеенная часовая свеча — уже не часовая, и подпись честно говорит, сколько свечей из скольких показано.
- **Шаг по индексу, а не по времени.** Иначе выходные и ночные перерывы сжимались бы в точку, а торговый день занимал бы треть ширины.
- **Интервал свечи — обычные ссылки** `?tf=1min…1mo`, по умолчанию день. Отдельной настройки «период графика» нет: окно задаёт сам интервал, поэтому дневной график — это год, а минутки — те пять дней, что отдаёт источник. Два переключателя перебивали друг друга и заставляли выбирать одно и то же дважды. Ссылки ведут с якорем `#chart`, иначе переход оставлял человека у шапки страницы. Канонический адрес — страница без параметров, иначе поисковик увидел бы десятки копий.
- **Выбранный интервал запоминается** в куке `tf` на год и общий для «Графиков», страниц инструментов и тикеров: выбрал «День» на одном графике — тот же интервал откроется на следующем. Порядок выбора: явный `?tf=` в адресе, затем кука, затем умолчание страницы (5 минут на «Графиках», день на тикере). Если запомненного интервала у рынка нет (у Мосбиржи нет 30 минут, на «Графиках» 10 минут), берётся ближайший по длительности. Поэтому параметр стоит у каждой ссылки интервала, включая умолчание: голый адрес означает «взять запомненный». Ответы, где интервал пришёл из куки, отдаются как `private`, а не в общий кеш.
- **Внутридневная страница не кешируется** (`no-store`): иначе человек полчаса видел бы минутные свечи пятиминутной давности.
- **Под графиком — таблица** в `<details>`: помесячные закрытия для дня и крупнее, последние свечи с OHLC для внутридневных.
- **Нет данных за интервал — нет графика, но есть переключатель.** Пустая рамка на каждой новой бумаге выглядит как поломка; ссылка «График» в верхнем меню появляется вместе с блоком.
- **Время подписано зоной** — московское, нью-йоркское или UTC: «09:47» без зоны у Газпрома и у AAPL означает разное время.

| Крипта | Binance, MEXC, Gate, CoinGecko | те же биржи | те же биржи |

- **CNBC режет датацентровые сети.** С этого сервера он отвечает 403 Akamai на свечи и котировки — и до появления запасного пути двадцать девять инструментов доски оставались пустыми. Порядок теперь обратный: сначала CNBC, при пустом ответе Yahoo (`lib/yahoo-instruments.js`), а ряд Yahoo подставляется только для инструментов, которые он знает.
- **Три доходности взяты у первоисточников** (`lib/yield-series.js`): десятилетние Германии — Bundesbank, Британии — Bank of England, двухлетние США — FRED. Yahoo их не знает, а `2YY=F` там оказался просроченным фьючерсом: неделями отдавал 4.78 против реальных 4.46.
- **FRED не отвечает на браузерный User-Agent** — соединение висит до таймаута. Для него отдельный запрос без этого заголовка.
- **У доходностей нет внутридневных значений.** Серия обновляется раз в день, поэтому на минутных интервалах доски показывается последний дневной ряд: пустая карточка читалась бы как поломка.
- **Котировки индексов идут отдельным путём.** `IDX:` — только восемь индексов из `INDEXES`; остальные бумаги доски берут цену через `fetchQuotes`, там же подставляется Yahoo.

- **Alpaca — основной источник по акциям США, но не единственный.** Без `ALPACA_KEY_ID` и `ALPACA_SECRET_KEY` всё работает на CNBC и Yahoo, как раньше. Отказ ключа (401/403) глушит Alpaca на десять минут, чтобы не долбить API каждые пять секунд, и запросы уходят на запасной путь.
- **Дневная история идёт пакетом.** 115 бумаг — это три запроса по 100 символов вместо 115 отдельных. Хранится в `charts.json` пять лет (`ALPACA_HISTORY_DAYS`), но на графике рисуется столько свечей, сколько читается, — обычно 120. Глубокая история нужна таблице и поисковику, а не картинке.
- **Внутридневные свечи — только хвост.** За прошлые периоды ничего не хранится: минутный час по 206 тикерам — это 150 тысяч свечей, которые устаревают к следующему показу. Окно в днях и лимит 400 свечей заданы в `INTRADAY` в `lib/alpaca.js`.
- **Внебиржевые часы отрезаются.** SIP отдаёт пре- и постмаркет, а Yahoo и CNBC — только основную сессию. Чтобы график не менялся от смены источника, свеча остаётся, если попадает в 09:30–16:00 по Нью-Йорку.
- **Изменение за день считается от прошлой сессии.** Сессию определяет день последней сделки, а не календарь: в субботу последняя сделка пятничная, и сравнивать её с пятничным закрытием значило бы показывать ноль все выходные.
- **Индексов, фьючерсов и валют у Alpaca нет.** 29 из 42 инструментов доски остаются на CNBC: `SPX`, `NDX`, `VIX`, нефть, металлы, доходности, FX.

## Раздел «Графики»

Раздел называется **«Графики»** в меню, подвале и хлебных крошках, а в `<title>` и `h1` — «Графики — …»: так его и ищут, а название категории остаётся в заголовке и описании. Адрес прежний — `/charts`, он уже проиндексирован. «Viz» и «Визуализация» нигде не показываются; внутреннее имя `VIZ` осталось только в ключах кеша (`VIZ:USD-RUB`) и адресах `/ticker/viz/…`.

`/charts` — сетка свечей по категориям рынков, `/charts/<слаг>` — страница одного инструмента. Разметка целиком серверная: поисковик не исполняет JS, а внешняя картинка ради графика означала бы лишний запрос и чужую зависимость.

### Наборы рынков

Инструментов 42, и 13 из них с Мосбиржи. Англоязычному читателю индекс ММВБ и ОФЗ в первой строке ни к чему, поэтому доска делится на наборы: **«Мир»** (29 инструментов CNBC), **«Россия»** (13 мосбиржевых) и **«Мир и Россия»** (все 42). Наборы не пересекаются — это ровно деление по источнику данных.

- **Набор по умолчанию зависит от языка адреса**, а не от куки или заголовков: `/en/charts` и `/es/charts` открываются на мире, `/ru/charts` — на общем наборе. Поисковик видит то же, что человек, ответ общий для всех и кешируется.
- **Набор попадает в адрес, только когда он не по умолчанию** (`?set=ru`, `?set=all`): голый `/en/charts` и есть мир, и второй адрес той же страницы был бы копией. Обратное тоже верно — `/en/charts?set=world` уводится 301 на голый путь.
- **`?set=` меняет и категории.** У «России» нет энергии, поэтому и кнопки такой категории нет (`catsOf`). Категория, которой в наборе нет, откатывается на «Все» — страница не должна отдавать пустую сетку из-за параметра в адресе.
- **Вкладка «Все» у каждого набора своя** (`pick` в `SETS`): по одному-два инструмента от категории. Прежние восемь ключей `ALL_KEYS` стали набором `all`.
- **Подзаголовок категории зависит от набора** (`leads`): «Мосбиржа и мировые площадки» над девятью мировыми индексами обещало бы то, чего на экране нет.
- **Описание считает размер набора, а не число карточек** (`setSize`): «восемь инструментов» на доске из 29 — обман.
- **hreflang считается заново для каждого языка** (`altPath` в `page()`): русским переводом `/en/charts` будет `/ru/charts?set=world`, а не голый `/ru/charts`, где набор другой. В `sitemap.xml` сочетания «набор × категория» идут семьями из трёх языковых адресов с взаимными `xhtml:link`.
- **Выбор набора — обычные ссылки без перехвата**: он меняет не только карточки, но и сами вкладки категорий, и половина страницы, перерисованная скриптом, разошлась бы с адресом. Перезагрузка здесь дешевле, и без скрипта работает так же.

- **Категории и интервалы переключаются без перезагрузки, но остаются ссылками.** Скрипт перехватывает нажатие и подменяет только нужный кусок через `/api/board` и `/api/chart`; без скрипта работает `href`, а canonical у всех интервалов и категорий один — адрес без параметров.
- **Меню стоит на одном месте на обеих страницах.** Полоса категорий и кнопки интервала (`catBar` + `tfBar` в `.gnav`) идут сразу под меню сайта и выше `h1`, внутри той области, которую скрипт заменяет. Поэтому при переходе с сетки на инструмент и обратно кнопки не сдвигаются, а длина заголовка и описания на них не влияет. Страница инструмента ради этого стала широкой, как сетка, и потеряла видимые хлебные крошки: дорогу назад показывает подсвеченная вкладка категории, а разметка `BreadcrumbList` осталась ради поисковой выдачи.
### Скрытие карточек и настройка доски

Крестик в углу карточки убирает её с доски, а вернуть убранное можно двумя путями: полосой **«Скрыто на этой вкладке»** прямо под сеткой (каждое — своей кнопкой, и тут же ссылка «все настройки») и страницей **`/charts/settings`**, где перечислены все 42 инструмента с галочками, в том числе те, что скрыты на других вкладках и наборах.

- **Выбор лежит в куке `vizhide`, а не в адресе.** Доска личная, и десятки её вариантов в индексе были бы копиями. `HIDE_COOKIE`/`parseHidden`/`hiddenValue` в `lib/markets.js`; разделитель — точка, потому что запятая в значении куки недопустима, а в слагах её нет. Неизвестные и повторные слаги отбрасываются, поэтому кука не растёт и не может спрятать то, чего нет.
- **Скрытое не запрашивается с биржи вовсе**: `marketFeed.board(... { hidden })` фильтрует список до загрузки свечей.
- **Крестик — форма, а не ссылка**: скрытие меняет состояние, и ссылку открыл бы любой предзагрузчик. Форма стоит рядом с карточкой (`.gcell > .ghide`), а не внутри неё: карточка целиком — ссылка, и кнопка в ней открывала бы инструмент.
- **Галочка на странице настройки означает «показывать», а хранится обратное** — список скрытых. Поэтому при сохранении список переворачивается; без этого отмеченные инструменты исчезали бы, а неотмеченные оставались.
- **С «Показать все» форма шлёт `do=reset`**, и это единственный способ вернуть всё разом, не снимая галочки по одной.
- **`back` в форме — адрес доски без языка**, ответ на форму сам добавит префикс. Принимается только путь, начинающийся с `/charts`: иначе форма уводила бы на произвольную страницу сайта.
- **Скрипт перерисовывает доску сам**: отправляет ту же форму с `X-Requested-With: fetch`, сервер отвечает 204 и ставит куку, а скрипт просит `/api/board` заново. Если запрос не удался — `form.submit()`, то есть честная перезагрузка.
- **Страница настройки — `noindex, no-store`**: она у каждого своя. Доска с непустым списком скрытых тоже отдаётся `private`, а не в общий кеш.
- **Пустая вкладка объясняется словами**: если скрыто всё, сетка не рисуется, и вместо неё стоит строка с дорогой к кнопкам. Полоса «скрыто» при этом показывает только инструменты текущей вкладки — список чужих карточек под пустой сеткой читался бы как ошибка.
- **Страница скрытого инструмента остаётся доступной**: скрытие касается доски, а не адреса. `sitemap.xml` не меняется — поисковик видит полный набор.

- **Ответ `/api/chart` для инструмента содержит меню, `h1` и график вместе.** Кнопки интервала стоят над заголовком, и кусок с одним графиком оставил бы подсвеченной прежнюю кнопку.
- **На сетке и на странице инструмента у ссылок интервала нет якоря `#grid`/`#chart`.** Полоса стоит у самого верха, и переход по якорю увёл бы её за экран — ровно туда, где её ищут. На странице тикера якорь остаётся: там график лежит ниже шапки и текста.

### Защита от чужих запросов

Порт открыт в интернет, а каждый новый тикер — это платный вызов модели. Два предохранителя:

- **Лимит генераций:** не больше `MAX_GENERATIONS_PER_HOUR` (по умолчанию 40) новых саммари в час на весь процесс. Попадания в кеш лимит не тратят. При превышении — 429 с понятным текстом.
- **Basic-авторизация:** задайте в `.env` строку `BASIC_AUTH=user:password` и перезапустите сервис — тогда весь сайт и API попросят пароль. Проверено: без пароля 401, с паролем 200.

`.env` не публикуется как статика (страницы отдаются только из `public/`), ключ BotHub в браузер не попадает.
